|---|---|---|---|
| **RC1** | **静摩擦 + 齿槽转矩构成"起动死区"**：本机实测脱开电流 ≈0.4A、运行电流 ≈0.15A（静/动摩擦比 ≈2.7），iq=0.3A 落在死区内，**净转矩=0，属于致动器物理能力问题，任何 PI 调参都改不了**。这是 ①的主因 | 代码自证（SPEED_FRICTION_* 标定值）+ 论文共识 | ① |
| **RC2** | **霍尔角度冻结自锁**：超过 `s_lost_limit` 无新边沿 → `s_angle_spd=0`（bsp_encoder.c:884-890），电流矢量在空间冻结成"电磁夹具"，转子被吸到 Δ=0 → 转矩=0 → 更无新边沿 → **自锁**。这是 ①"0.3 完全不转、0.4 就转"这种阶跃式阈值的代码级放大器 | 代码逻辑 + 物理推理 | ① |

| **RC4** | **摩擦前馈状态机 = 自激松弛振荡器**：REST 时每 1ms 强清积分（PID.c:281）+ 前馈 150ms 爬到 0.75A → 脱开后立刻掉到 0.35→0.15A；加上 **200rpm 以下禁刹钳位**（PID.c:357-380）和 ±90rpm 的测速量化，构成"猛冲→掉速→再猛冲"的极限环，周期 ≈ 一转（600ms）。这是 ②的主因 | 代码逻辑 + 现象周期吻合 + 论文（极限环/滞滑）共识 | ② |
| **RC5** | **霍尔测速反馈质量差**：100rpm 时 10ms 固定窗净位移 → **±90rpm 阶梯量化**；单边沿 T 法 25ms 采样保持 + 30Hz 低通 → **≈35~40ms 反馈延迟**。速度环有效带宽被压到 ~0.5Hz 级 | 计算 + Microchip/mjbots/MDPI 综述共识 | ② |
| **RC6** | 电流环相位裕度不足：三相电流各串一个 α=0.2 一阶低通（≈640Hz 极点），300Hz 设计带宽处三极点吃掉 ≈75°，相位裕度仅 ~13° | 计算 | ①② |
| **RC7** | 两个现成工具是死代码：`HALL_LOST_DECAY_RS`（配置有、没用）、`PLL_Loop`（初始化了、从未调用）——恰好分别是 RC2、RC5 的正解 | 代码事实 | —— |

> **一句话**：①是"**力不够 + 角度源不动**"两个问题叠在一起（力不够是物理，角度冻结是代码）；②是"**速度环被自己的前馈状态机和禁刹钳位搞成自激振荡 + 测速反馈太差**"。位置环不动的要求不影响以下方案，但内环改完后位置环参数需重新整定。

## 1. 文献调研：网上方案与论文的共识

### 1.1 低速爬行（crawling / stick-slip）的物理本质

论文共识：摩擦的"静大于动 + Stribeck 负斜率"是低速爬行的根源。系统以恒速目标运行时，出现"静→动→静→动"交替的跳跃运动，即爬行现象。

- 《高精度伺服系统低速问题研究》（自动化学报）用相平面 + Lyapunov 给出三阶系统克服低速滞滑的判定定理：**增大系统阻尼比和转折频率可减少滞滑运动**；摩擦模型为 Stribeck（静摩擦=库仑+Stribeck 项，动摩擦=库仑+粘滞）。
  https://www.aas.net.cn/cn/article/pdf/preview/16160.pdf
- 《A Review of Key Technologies for Friction Nonlinearity...》（MDPI 机器 2022）明确：爬行 = 运行速度低于某临界值时速度脉动，本质是静/动摩擦系数差导致的断续运动。
  https://www.mdpi.com/2075-1702/10/7/568
- 长春光机所《伺服系统受摩擦扰动产生极限环的原因及稳定性分析》：用 Poincare-Bendixson 定理证明 **低速摩擦（Stribeck）必然产生极限环**，且可判定其稳定性 —— 这正是 RC4"自激振荡"的数学依据。
  https://ir.ciomp.ac.cn/bitstream/181722/3186/1/伺服系统受摩擦扰动产生极限环的原因及稳定性分析.pdf

**工程启示**：低速平滑不是"把 PI 调软"能解决的，必须 ①给足并保持脱开力矩（摩擦前馈/连续摩擦模型）②提高反馈质量以允许更高阻尼 ③必要时用抖动/开环强拖"抖过"静摩擦峰。

### 1.2 霍尔传感器低速测速的三个学派（MDPI 综述）

《Application of Low-Resolution Hall Position Sensor in Control and Position Estimation of PMSM—A Review》（Energies 2024, 17, 4216）把霍尔测速/位置估计方法分为三类：

1. **插值法**（平均速度法 / 平均加速度法 / 最小二乘法）：简单但会引入相位滞后和噪声，闭环性能受限；平均加速度法在速度波动大时反而引起脉动；最小二乘用于校正霍尔安装误差。
2. **滤波法**：如滑动平均、低通；同样有延迟。
3. **观测器法**（PLL / Kalman / 滑模等）：精度最高，可提供连续平滑的速度，**是低速霍尔驱动的推荐做法**；缺点是对电机参数敏感。

https://www.mdpi.com/1996-1073/17/17/4216

**对照本项目**：bsp_encoder.c 用的是"插值法（六边沿平均速度外推）+ 固定窗净位移测速 + 30Hz 低通"，恰是综述里"相位滞后大、低速量化严重"的那类。**升级路径 = PLL/观测器法**（代码里 PLL.c 现成）。

### 1.3 起动问题：I-F 开环强拖是行业标准答案

零低速时位置/反电动势信息不可靠，所有厂家都用"开环强制换相把转子拖起来，到能观测的速度再平滑切闭环"：

- MDPI《Instant Closing of PMSM Control Systems at Open-Loop Start》：I-F 起动 = 速度环开路、电流闭环，按预设频率斜坡 + 电流幅值把电机加速，再无缝切换。
  https://www.mdpi.com/2071-1050/14/19/12665
- 电工技术学报《基于改进型 I-f 控制的永磁同步电机无位置控制》：I-f 存在欠阻尼振荡问题，**加入频率补偿/阻尼增强**可抑制起动振荡并快速平滑切入闭环。
  https://dgjsxb.ces-transaction.com/fileup/HTML/2025-12-3895.htm
- TI（InstaSPIN/MotorWare）与 ST（MC SDK）官方起动流程同样是"Align → 开环斜坡 → 切换闭环"，切换点取额定转速 10~15%。

**对照本项目**：代码已有 ALIGN→CALIB→DIRCHK→RUN 流程，但 RUN 之后完全依赖霍尔角度；**缺一个"低速角度助推（I-F 式）"层**。霍尔是绝对位置传感器，不需要无感 I-F 那么复杂的切换，只需在低速段让施加角主动外推（见 3.1 P0-A）。

### 1.4 死区补偿：低速小电流的必备项

- ST AN5397《Current sensing in motor control applications》、AN4144 等应用笔记：逆变器非线性（死区+管压降）在低电流下造成电压误差与电流畸变，需按相电流符号补偿。
- IEEE《A Study on the Improvement of Flux-Based Torque Control Performance Through Compensation of Voltage Error Caused by Dead-Time》（2026）等大量论文：死区误差是**绝对电压误差**，高速大电流可忽略，低速小电流占主导。
- 中文综述《空间低速直驱伺服系统低频谐波电流分析与抑制》（北航学报）：电流检测偏置、绕组不对称、齿槽效应是低速直驱伺服**普遍存在**的三种力矩纹波源。

**对照本项目**：0.171V 死区误差 vs 0.1245V 的 0.3A 指令电压，比值 1.4 倍 —— 不做补偿，低 Iq 转矩指令本身就是"糊"的。

### 1.5 齿槽转矩补偿（Cogging LUT）—— 开源实践

- ODrive：`anticogging` 标定 —— 位置环保持 + 微扰，记录每个电角度所需的补偿力矩，拟合成傅里叶表，按电角度前馈注入电流环。官方文档明确"对齿槽严重的电机，这是消除低速阶跃/卡顿的关键"。
  https://docs.odriverobotics.com/v/latest/manual/control.html
  https://drives.novantamotion.com/kb/cogging-compensation.md
- SimpleFOC 社区：对齿槽大的电机，低速阶跃运动"是自然现象"，提高 PID 增益可能只是失稳；正解是 cogging 补偿表或改用 angle_nocascade 结构。
  https://community.simplefoc.com/t/how-do-you-improve-slow-speed-control/7712/2

**对照本项目**：本机 0.4A 脱开阈值随转子位置变化的部分就是齿槽，做一个按电角度的摩擦+齿槽 LUT 可以把"死区宽度"压掉大半（见 3.1 P2）。

### 1.6 霍尔测速的工程级改进 —— mjbots/moteus 的实践

mjbots（moteus 伺服）2025 年博客《Improved hall effect encoder performance》直接讲"霍尔编码器低速性能"：

- 低分辨率霍尔直接进 PLL 滤波器 → 速度估计"阶梯 + 尖峰"（每次采样保持 0，边沿瞬间冲高再回落）—— 与本项目现象一致；
- **正解 = 双模式动态切换**：低速用**边沿间计时**（T 法，精度高），高速用 PLL 滤波；切换阈值取 PLL 截止时间常数的 1/4，并用**迟滞计数（连续 3 个样本）**防止模式抖振；
- 霍尔安装不均匀导致恒速下相邻边沿间隔波动，切换阈值附近必须有迟滞，否则两模式来回跳。

https://blog.mjbots.com/2025/07/31/improved-hall-performance/

**对照本项目**：现有"低速净位移(固定窗) + 高速 T 法"融合与 mjbots 思路同源，但低速支路用了 10ms 固定窗 → ±90rpm 量化；**应把低速支路换成"边沿间计时 + PLL"，并给融合加迟滞**（见 3.2 P1）。

### 1.7 业界零速/低速方案（ST）

ST 的 HSO（高灵敏度观测器）+ ZeST（零速全转矩）算法：无感模式下从零速到高速控制 PMSM，核心思想就是**低速时不用反电动势、用观测器/注入法撑住角度，到中高速切反电动势 PLL**。
https://www.st.com.cn/content/st_com/zh/ecosystems/stm32-motor-control-ecosystem/stm32-zest-and-hso-solutions.html

**对本项目的意义**：证明"低速角度不能靠自然外推，必须主动观测/强制"是行业共识；霍尔版实现比无感简单得多（有绝对位置锚点）。

## 2. 代码现状与根因判定（结合文献复核）

### 2.1 问题①：扭矩模式 iq=0.3A 完全不转、0.4A 能转

**根因 1（主因）：静摩擦+齿槽起动死区（物理，调参无解）**

代码自己的标定数据（SPEED_FRICTION_* 注释）：
- 运行电流 ≈0.15A（KINETIC_A），实测脱开 ≈0.4A（扭矩模式无前馈时），静/动比 ≈2.7，死区宽度 ≈0.25A。
- 0.3A = 脱开力的 75%，转子受到的净转矩 = 0（静摩擦的"硬死区"特性，见 §1.1）。
- 实验判据：**iq=0.3A 静止后用手轻推转轴一下，若能自己持续转下去 ⇒ 纯摩擦死区**（若推完会自己停，则另有齿槽/角度问题）。

**根因 2（代码级放大器）：霍尔角度冻结自锁**

`HALL_GetElecAngle()`（bsp_encoder.c:867-917）：
```c
if (lost > (uint32_t)s_lost_limit) {
    s_phase_trim = 0.0f;
    s_angle_spd  = 0.0f;          /* ① 角度停止外推 */
}
...
s_hall_ang = ... + (s_angle_spd + s_phase_trim) * ts;
/* ② 60° 扇区硬钳位（897-909）：估算角永不超出当前霍尔扇区 */
```
后果：静止 → 40~75ms 无新边沿 → 角度冻结 → 电流矢量变"静止磁铁" → 转子被吸到 Δ=0 → 转矩=0 → 更无新边沿 → **自锁**。0.4A 能转是因为初始那一下推动跨过了一个边沿，角度恢复外推形成正反馈。注释里"旧写法在换向瞬间把整条积分清零，估算角度冻死，电机随后卡住"就是同一条故障路径的另一个触发条件。

**根因 3（模糊化）：死区电压畸变**（见 §1.4）：0.171V vs 0.1245V。

**根因 4（次要）：电流采样**：10mA/LSB，0.3A 只有 30 个码值；零点漂移 1LSB = 3.3% 转矩误差。

**确认实验**（按序做，10 分钟）：
| 实验 | 做法 | 判读 |
|---|---|---|
| A | iq=0.3 静止后手推转轴一下 | 推完持续转 ⇒ 角度冻结自锁为主；推完即停 ⇒ 纯摩擦死区 |
| B | VOFA 看 Iq 实际值是否稳定 0.3A、Theta 是否不动 | Iq 稳 + Theta 不动 ⇒ 确认根因 2 |
| C | 转子停在 6 个不同霍尔扇区重复 0.3/0.4 实验 | 阈值随位置起伏 ⇒ 齿槽成分大 |
| D | 空载/带载对比 | 带载阈值上移 ⇒ 摩擦成分大 |

### 2.2 问题②：速度模式 100rpm 一转一停

**根因 1（主因）：摩擦前馈状态机 = 松弛振荡器（代码特有）**

100rpm 目标下（1 转 = 600ms）：
```
转速掉到 ≤10rpm
   │
   ▼
FRICTION_REST（PID.c:270-278）
   · pid.Integral 被强清 0，之后每 1ms 再清一次（PID.c:281）→ 速度环永远建不起稳态力矩
   · 前馈 0.15A 在 150ms 内爬到 0.75A（远大于实际脱开 0.4A）→ 猛冲
   │
   ▼
转速窜到 ≥20rpm
   │
   ▼
FRICTION_MOVING（PID.c:250-258）
   · 前馈立刻跌到 0.35A，80ms 内衰减到 0.15A ← 脱开瞬间掉 0.4A 力矩台阶
   · PI 积分器刚被清零、从 0 重新爬
   │
   ▼
合力矩 < 动摩擦 → 转速再次掉到 ≤10rpm
   └────────────► 回到起点（周期 ≈ 150+80ms + 爬行时间 ≈ 一转）
```
数学依据：§1.1 长春光机所的极限环定理 —— Stribeck 摩擦下这种"开关式补偿 + 积分清零"结构必然自激。配置注释"0.0025 会增加停顿点，0.004 已验证振荡"正是这个结构的表现。

**根因 2（反馈质量）：霍尔测速量化 + 延迟**

- 100rpm：霍尔边沿 40Hz（25ms/边沿），24 边沿/机械转；
- 10ms 固定窗净位移：窗口只跨 ~0.4 个边沿，估算在 0 / 90rpm 间跳变 → **±90rpm 阶梯**（50ms 延迟已被注释否定过，10ms 是当前折中）；
- 单边沿 T 法：25ms 采样保持 + 30Hz 低通 → 总延迟 ≈35~40ms；
- 速度环 1kHz 执行，但有效带宽被压到 ~0.5Hz（延迟 35ms ⇒ 穿越频率 ≲ 1/(10×0.035)≈2.9rad/s）。

**根因 3（帮凶）：禁刹钳位**

PID.c:357-380：目标 ≤200rpm 且 PI 想反向时，转速在"目标±30rpm"内 Iq 直接置 0，只留 0.10A 制动权限 —— **100→130rpm 段完全没有制动力矩**，只能靠摩擦自然掉速，是"冲高-掉速"极限环的另一半。

**根因 4：电流环相位裕度**（§0 RC6）：三路电流 LPF（α=0.2，≈640Hz）在 300Hz 处合计吃 ≈75°。

**确认实验**：
| 实验 | 做法 | 判读 |
|---|---|---|
| A | VOFA 加日志：ff 电流、friction_state、rpm、Iq 指令（见 §4） | 期待看到 1.67Hz 周期、ff 0.15→0.75 锯齿、state 在 REST↔MOVING 来回跳、超速段 Iq 被压 0 |
| B | 临时把 SPEED_FRICTION_STATIC_A 从 0.75 降到 0.25、SPEED_NO_BRAKE_RPM 从 200 降到 110 | 卡顿周期明显变化/消失 ⇒ 确认 RC4 |
| C | 100rpm 恒定，VOFA 看 f_speed_fb | ±80~90rpm 阶梯 ⇒ 确认 RC5 |

## 3. 解决方案

### 3.1 问题①（扭矩模式低 Iq 起动）

#### P0-A：低速角度助推（I-F 式强制换相）【推荐，正式方案】
在 `Run_UpdateObserver()` 里，低速段让施加电角度主动以受限加速度外推，转子被"拖"过静摩擦/齿槽峰；转速上来、霍尔外推恢复后再平滑切回（角度用最短径插值融合，禁止硬切）。这正是 §1.3 的 I-F 思想在霍尔版里的落地。配置建议：
```c
#define ANGLE_ASSIST_ENABLE     1
#define ANGLE_ASSIST_IQ_MIN     0.05f    /* |iq指令| 低于此值不助推 */
#define ANGLE_ASSIST_RPM_ENTER  60.0f    /* 机械转速低于此进入助推 */
#define ANGLE_ASSIST_RPM_EXIT   90.0f    /* 高于此退出(迟滞) */
#define ANGLE_ASSIST_W_MAX      20.0f    /* 电角速度上限 rad/s ≈48rpm机械 */
#define ANGLE_ASSIST_W_ACC      150.0f   /* 电角加速度 rad/s^2 */
#define ANGLE_ASSIST_BLEND_MS   100U     /* 切回融合时间 */
```
实现要点：助推角以当前霍尔角为起点（角度连续不冲击）；退出用 0→1 权重在 100ms 内融合到霍尔角；只在 |iq|>0.05 且 |rpm|<60 时启用，位置模式可关。

#### P0-B：角度抖动 dither【最小改动，先验证方向】
低速小电流时给施加角叠加 20Hz、±20° 电角的低频摆动，把静摩擦"抖"成动摩擦（经典抗粘滑手段，§1.1）。改动 <10 行；缺点：平均转矩损失约 6%，可能引入可闻噪声。**建议先做 B 验证（半天），再上 A。**

#### P1：死区补偿【强烈建议，顺带解决 ② 低速平滑】
按相电流符号补偿 ±0.171V，近零电流（|i|<0.05A）线性过渡避免抖动。实现见旧文档 P1-C（约 15 行，在 PI_Current_Loop 之后、SVPWM 之前对 Vd/Vq 补偿）。系数/符号必须实测标定。
```c
#define DEAD_TIME_S     357e-9f
#define DEAD_TIME_V     ((DEAD_TIME_S / (1.0f/Tim_Hz)) * _Udc)  /* ≈0.171V */
#define DEAD_IZERO_A    0.05f
/* cu/cv/cw = lin_sign(相电流, 死区), 投影到 dq 后 Vd/Vq -= DEAD_TIME_V*c*0.5 */
```

#### P2：摩擦 + 齿槽前馈 LUT【进阶，压死区宽度】
按电角度（用 PLL 平滑角，不要用霍尔扇区角）建立 72~128 点前馈电流表：低速背拖/开环 VF 慢转，记录每个电角度的维持电流，多圈平均分离齿槽与随机摩擦。ODrive 的 anticogging 就是这做法（§1.5）。**只做这个就能把 0.4A 阈值中随位置变化的部分压掉大半。**

#### P3：最小输出电流钳位（breakaway snapping）
若 `0 < |iq_cmd| < 脱开电流`，驱动方向时直接抬到 ±脱开电流（带迟滞：进入阈值 = 脱开电流，退出 = 0.7×脱开电流），避免在死区内"命令了但不动"。注意只能用于"驱动"语义（速度/位置），不能用于制动。

#### P4：顺手项
- ADC 注入采样时间 3 → 28 周期（Core/Src/adc.c:78）：小电流精度；
- ALIGN_CURRENT_ID 0.5→0.8~1.0A、ALIGN_TIME_MS 1000→1500ms：零点更准（相位误差直接吃掉 cos(δ) 转矩）；
- 用起来 `HALL_LOST_DECAY_RS`：把"无新边沿时角度硬清零"改成"按 60rad/s² 衰减到 0.2rad/s 下限"，起停过渡更顺（不能替代 P0-A）。

### 3.2 问题②（速度模式 100rpm 卡顿）

#### P0-C：拆掉速度环自激结构【最高优先级，免费改动】
1. **删掉 PID.c:281 的 `sc->pid.Integral = 0.0f;`**，改成积分限幅 ±SPEED_FRICTION_KINETIC_A（≈0.15A）。让积分器把"维持力矩"建起来并保持，前馈只做辅助（§1.1：稳态力矩靠积分，前馈负责快速过峰）。
2. **前馈连续化**：把 4 状态机换成连续摩擦模型（Coulomb + Stribeck/粘滞，见旧文档 P0-C 公式）：ff 必须是 rpm_target 和 fb_rpm 的连续函数，去掉 0.75→0.35→0.15 的台阶；或用一阶惯性在 MOVING 后把 STATIC_A 平滑衰减到 KINETIC_A（时间常数 150~300ms，且**保持 ff ≥ 脱开电流直到 rpm ≥ 0.8×目标**）。
3. **放开禁刹钳位**：`SPEED_NO_BRAKE_RPM` 改为随目标自适应（= rpm_target + OVERSHOOT）或直接降到目标附近；`SPEED_OVERSPEED_BRAKE_A` 从 0.10A 提到 ≥0.25A（必须大于动摩擦 0.15A，否则刹车连摩擦都打不过）。
4. 以上改完，速度环 Kp/Ki 重新整定（先 Ki=0 只调 Kp 到临界再退一半，再加 Ki）。

#### P0-D：启用现成的 PLL 转速观测器【反馈质量的正式解】
`PLL_Loop()` 已写好、从未调用（StateMachine.c 只做了初始化和对齐）。在 `Run_UpdateObserver()` 里每拍调用：
```c
PLL_Loop(&state->PLLParm, HALL_GetMechAngle());   /* 连续机械角，无回绕 */
float rpm_pll = RPM_FROM_WE(state->PLLParm.OutWe * HALL_POLE_PAIR);
```
- 现有 kp_theta=300 / ki_theta=20000（ωn≈141rad/s，ζ≈1.06，按电角整定）。喂机械角时转速慢 4 倍，等效 ωn≈35rad/s、ζ 不变 —— **对 100rpm 正合适**，先用现成参数观察波形再微调。
- PLL 输出连续、无阶梯、延迟远小于"10ms 窗 + 30Hz 低通"；之后可以把 `SPEED_FB_LP_HZ` 的 30Hz 低通去掉或提到 100Hz+（PLL 自带限带）。
- 高低速融合：低速用 PLL 输出，高速仍用单边沿 T 法，中间按转速加权（现有 `HALL_SpeedObserver_Update` 的框架可直接改，把 mech_rpm 换成 PLL 输出）。

#### P1：测速双模式切换 + 迟滞（mjbots 方案，§1.6）
把"固定 10ms 窗净位移"换成"边沿间计时（T 法）为主、PLL 平滑为辅"，切换阈值按 PLL 截止时间常数（≈其 1/4），并加连续 3 样本迟滞防止模式抖振。这直接消灭 ±90rpm 阶梯。工作量中等，P0-D 落地后优先级可以降低。

#### P2：目标斜坡 + 加速度前馈
- 目标转速 0→100rpm 用 ≥300ms 的 S 形/梯形斜坡，避免阶跃直接撞进脱开区（旧文档 P0-E）；
- 可选：辨识 J 后加 `iq_ff = J·dω/dt / Kt`，把启动过冲大部分吃在前馈里。

#### P3：电流环相位裕度
`filter.c:546-548` 三相电流 LPF α 0.2 → 0.5（≈2.2kHz 极点，300Hz 处每级只吃 8°），或直接旁路；配合 P1-B 的 ADC 采样时间延长。同时可把 CURRENT_BW_HZ 300→250。
