## 0. 结论摘要（先看这里）

| # | 结论 | 影响 | 改动量 |
|---|---|---|---|
| **RC1** | **低速/静止时霍尔电角度会"冻结在原地"**。`HALL_GetElecAngle()` 在超过 `s_lost_limit` 没有新霍尔边沿时把 `s_angle_spd` 直接清零（`bsp_encoder.c:885-890`），角度不再前进；再叠加"估算角必须落在当前 60° 扇区内"的硬钳位（`bsp_encoder.c:897-909`）。**电流矢量在空间里冻结后，转子会被这个静止的磁场"吸"到 Δ=0 的位置（转矩=0）并停住 —— 这正是一个电磁铁/步进电机定位行为，不是摩擦问题。** | ①的**主因**；②的"停下起不来"那一半 | 中 |
| **RC2** | **摩擦前馈状态机本身就是一个自激振荡器**：REST 状态下每 1ms 把 `pid.Integral` 强清零（`PID.c:281`），同时把前馈从 0.15A 在 150ms 内爬到 0.75A（`PID.c:282-290`）；一旦转速过 20rpm 立刻降到 0.35A 并在 80ms 内衰减到 0.15A。**积分器被反复清零 → 速度环永远建不起稳态力矩 → 只能靠前馈"猛冲 → 掉下来 → 再猛冲"**。 | ②的**主因**（一转一停） | 中 |

| **RC6** | **ADC 注入采样时间只有 3 个 ADC 周期**（`adc.c:78`，≈143ns @21MHz）。采样保持电容在这么短的时间内充不满，小信号时增益误差/非线性被放大。 | ①（小电流精度） | 极小 |
| **RC7** | 代码里存在**两个死功能**：`HALL_LOST_DECAY_RS`（配置里定义了"丢失边沿后按时间常数衰减外推速度"，全工程未使用）、`PLL_Loop()`（`StateMachine.c:57-58` 和 `197-205` 只做了初始化和状态对齐，**从未调用过 `PLL_Loop`**，所以"PLL 转速观测器"完全没在工作）。这两个恰好是解决 RC1 和 RC3 的现成工具。 | 参考价值 | —— |

> 一句话：**①是"角度源在低速没有运动"，②是"速度环被自己的摩擦前馈和禁刹钳位搞成了自激振荡"。两者都不是"参数没调好"，改参数只能在错误的结构里打转（配置注释里已经有 `0.0025 会增加停顿点 / 0.004 已验证振荡`，正说明这一点）。**

```
                Clarke → Park → PI_Current_Loop (T=50us, Kp=2.337, Ki=782.2)
                switch(state)   ALIGN→ALIGN2→CALIB→DIRCHK→RUN
                RUN: Run_UpdateObserver()  // Theta = HALL_GetElecAngle()

                FOC_Algorithm_SVPWM  (7 段 SVPWM, Tmin/Tmid/Tmax)
                Motor_SetPWMCompare(CCR_U/V/W)
```

关键量：
- 电流分辨率 **10.0 mA/LSB**（`k = 3.3/(4095*4.023*0.02)`），0.3A = 30 个码值。
- 极对数 4，霍尔每 60° 电角一个边沿 = 每 15° 机械角一个边沿 = **每机械转 24 个边沿**。
- **100rpm 时霍尔边沿间隔 = 25ms（40Hz）**；`s_lost_limit = 3×上次周期`（`bsp_encoder.c:846-850`，钳位 40~400ms）。
- 速度反馈：100rpm < `SPEED_MEAS_LOW_RPM 200` → `fused_rpm = mech_rpm`（10ms 滑动窗净位移，`bsp_encoder.c:318`），再经 30Hz 低通 → 有效延迟 ≈ 10ms。
- 扇区内角度靠 `s_angle_spd`（最近 6 个同向霍尔周期的平均）+ `s_phase_trim` 线性外推（`bsp_encoder.c:895-896`）。

## 2. 问题①：扭矩模式 iq=0.3A 完全不动，0.4A 能转

### 2.1 根因：低速时"电角度源没有在转"

`HALL_GetElecAngle()` 每 50us 执行一次，核心三行（`bsp_encoder.c:884-896`）：

```c
lost = s_ms_tick - s_edge_ms;
if (lost > (uint32_t)s_lost_limit) {
    s_phase_trim = 0.0f;
    s_angle_spd  = 0.0f;          /* ← 角度停止前进 */
}
...
s_hall_ang = HALL_Wrap0To2Pi(s_hall_ang + (s_angle_spd + s_phase_trim) * ts);
```

`lost` 一旦超过 `s_lost_limit`（静止时它保持上一次运行留下的值，上电初值是 `HALL_EDGE_LOST_MS_MIN = 40ms`），**外推速度被清零，`s_hall_ang` 就固定不动了**。

后果是一个很基本但很容易被忽略的物理事实：

> 施加的电流矢量在定子上是一个**静止的磁动势矢量**。转子的永磁 d 轴会被吸到这个矢量的方向上（Δ→0），**达到平衡后 q 轴电流依然存在，但产生的转矩 = Kt·Iq·cos(Δ) = 0**。

也就是：**角度冻结之后，驱动器退化成一个"电磁夹具"，不是电机。它只会把转子吸住，绝不会持续旋转。**

这正是为什么阈值那么"硬"、且与位置无关：
- 静止 → 40~75ms 内没有新边沿 → `s_angle_spd = 0` → 角度冻结 → 转子被吸到 Δ=0 → 停；
- **只要转子没有跨过霍尔边沿，就永远拿不到新的 `s_angle_spd`，永远解不开这个锁**（自锁）；
- iq=0.4A 时，初始那一下推动能在冻结生效前跨过一个霍尔边沿，于是 `s_angle_spd` 更新为真实转速，形成正反馈（转得动→有边沿→角度跟着走→转得动），才能起来；
- iq=0.3A 时初始那一下推不动/推不够，就在冻结生效后被吸住，**死锁**。

这解释了"0.4 转、0.3 完全不转"这种**阶跃式**阈值——纯静摩擦不会这么干脆（齿槽会让阈值随转子位置起伏）。

### 2.2 代码自己就记录过这个坑

`bsp_encoder.c:891-892` 的注释：

> `方向守卫只限制校正量 s_phase_trim；绝不能拿它限制实测转速 s_hall_spd：`
> `旧写法在换向瞬间把整条积分清零，估算角度冻死，电机随后卡住。`

**"估算角度冻死，电机随后卡住"——就是现在这条 `s_angle_spd = 0` 路径造成的同一个故障，只是换成了"长时间无边沿"这个触发条件。**

`bsp_encoder.c:897-901` 的 60° 扇区钳位同样在加固这个行为：它保证估算角**永远不会超出当前霍尔扇区**，所以外推最多再把角度推进 60° 电角（15° 机械）就到头了。注释里把"转矩方向永不反转"当成优点，但代价是**低速时角度源完全没有"继续前进"的能力**。

另外，配置里已经定义好但**从没被调用**的 `HALL_LOST_DECAY_RS = 60.0f`（见 `Motor_Config.h`，全工程 grep 无引用），说明原设计意图本来就是"丢失边沿后按时间常数衰减外推速度"，而不是硬清零。

### 2.3 先用 5 分钟把结论坐实（**强烈建议先做这一步**）

| 实验 | 做法 | 判据 |
|---|---|---|
| **A（最关键）** | 扭矩模式设 `iq = 0.3`，电机静止后**用手轻推转轴一下** | 推完能**自己持续转下去** ⇒ 100% 确认是"角度冻结/起动"问题（若真是静摩擦>0.3A·Kt，推完会自己停） |
| **B** | 扭矩模式 VOFA 看 `Id实际/Iq实际`（当前扭矩模式已经能看这 4 路，`VOFA.c:31-34`） | `Iq实际` 稳定在 0.3A 且电机不动 ⇒ 电流环/采样没问题，问题在角度或摩擦 |
| **C** | iq=0.3，把转子故意停在**不同霍尔扇区位置**重复实验 | 阈值基本一致 ⇒ 角度冻结自锁；阈值随位置明显起伏 ⇒ 齿槽/静摩擦占主导 |
| **D** | 同一实验在**空载/带载**下对比 | 带载时阈值大幅上移 ⇒ 摩擦成分更大 |

实验 A 通过就按 2.4 的 P0-A 改。

### 2.4 解决方案

#### P0-A（推荐）低速开环角度助推 —— I/F 强制换相 + 平滑切换

这是低分辨率位置传感器/无感驱动在零低速的标准做法：**零低速时反电动势/位置信息不可用，必须用开环硬拖（I-F）把转子拉起来，到能观测的速度后再平滑切回位置反馈**（参见 [`foc-sensorless` 参考文档](https://cdn.jsdelivr.net/npm/auto-embedded@1.1.4/templates/auto-embedded/refs/foc-sensorless.md)：*"零/极低速反电动势≈0、观不出来，必须靠凸极效应(HFI)或开环硬拖(I-F)"*、*"切换瞬间是失步高发点：必须做角度对齐 + 渐变权重，禁止硬切"*）。

在 `Motor_Config.h` 新增：

```c
/* ---------- 低速开环角度助推 (I/F 起动) ---------- */
#define ANGLE_ASSIST_ENABLE     1
#define ANGLE_ASSIST_IQ_MIN     0.05f    /* |iq指令| 低于此值不助推 */
#define ANGLE_ASSIST_RPM_ENTER  60.0f    /* 机械转速低于此值进入助推 */
#define ANGLE_ASSIST_RPM_EXIT   90.0f    /* 高于此值退出助推(迟滞) */
#define ANGLE_ASSIST_W_MAX      20.0f    /* 助推电角速度上限 rad/s (机械≈48rpm) */
#define ANGLE_ASSIST_W_ACC      150.0f   /* 电角加速度 rad/s^2 */
#define ANGLE_ASSIST_BLEND_MS   100U     /* 切回霍尔角的融合时间 */
```

在 `Run_UpdateObserver()` 里，读完 `fused_rpm` 之后接一段：

```c
static float s_as_w, s_as_ang;      /* 助推电角速度 / 助推角 */
static uint16_t s_as_blend;         /* 融合计数 */
static uint8_t  s_as_on;

float fb_rpm = state->speed.f_speed_fb;
float iq_cmd = state->current.q.Target;

if (fabsf(iq_cmd) > ANGLE_ASSIST_IQ_MIN && fabsf(fb_rpm) < ANGLE_ASSIST_RPM_ENTER) {
    if (!s_as_on) {                 /* 进入助推：以霍尔角为起点，避免冲击 */
        s_as_on  = 1U;
        s_as_ang = state->FOCParm.Theta;
        s_as_w   = 0.0f;
    }
    float dir = (iq_cmd >= 0.0f) ? 1.0f : -1.0f;
    s_as_w += dir * ANGLE_ASSIST_W_ACC * ts;
    if (s_as_w >  ANGLE_ASSIST_W_MAX) s_as_w =  ANGLE_ASSIST_W_MAX;
    if (s_as_w < -ANGLE_ASSIST_W_MAX) s_as_w = -ANGLE_ASSIST_W_MAX;
    s_as_ang = wrap_2pi(s_as_ang + s_as_w * ts);
    s_as_blend = 0U;
} else if (s_as_on) {
    if (fabsf(fb_rpm) > ANGLE_ASSIST_RPM_EXIT) {
        s_as_blend++;               /* 到速：用 0→1 权重把角度从助推角融到霍尔角 */
        if (s_as_blend >= ANGLE_ASSIST_BLEND_MS) { s_as_on = 0U; s_as_blend = 0U; }
    } else {
        s_as_blend = 0U;
        s_as_w = 0.0f;              /* 转速掉了但没到退出速度：停助推等重新起 */
    }
}

/* 角度选择/融合 */
float theta_hall = state->FOCParm.Theta;    /* HALL_GetElecAngle 的原始输出 */
if (s_as_on) {
    float k = (float)s_as_blend / (float)ANGLE_ASSIST_BLEND_MS;  /* 0=全助推,1=全霍尔 */
    float d = wrap_pi(s_as_ang - theta_hall);
    state->FOCParm.Theta = wrap_2pi(theta_hall + (1.0f - k) * d);
}
```

要点：
- 助推角**以当前霍尔角为起点**，切换时角度连续，不会打人；
- 融合用最短径插值（`wrap_pi`），100ms 内完成，过渡期不会失步；
- 转速一旦超过 60rpm，霍尔边沿每 ≤40ms 来一次，外推恢复工作，自然接管；
- `ANGLE_ASSIST_W_MAX = 20 rad/s` 电角 ≈ 48rpm 机械，转子极易跟随（远低于失步点）。

#### P0-B（最小改动版，可先试）——角度抖动 dither

如果暂时不想动角度源结构，可以只在低转速段给施加角叠加一个低频抖动，让电流矢量围绕霍尔估算角小幅摆动，把静摩擦"抖"成动摩擦（经典抗粘滑手段）：

```c
/* 仅当 |iq|>0.05 且 |rpm|<40 时启用 */
static float s_dither_ph;
s_dither_ph += _2PI * 20.0f * ts;                     /* 20Hz */
if (s_dither_ph > _2PI) s_dither_ph -= _2PI;
float dither = 20.0f * _PI / 180.0f * sinf(s_dither_ph);   /* ±20° 电角 */
state->FOCParm.Theta = wrap_2pi(state->FOCParm.Theta + dither);
```

优点：改动 <10 行、不会失步、位置环模式可以关掉。
缺点：只是"推一把"，对 iq=0.3 能不能起来需要实测；且会给电流环引入一个 20Hz 的 d 轴扰动（幅值不大，`cos(20°)=0.94`，转矩平均损失 6%）。

> 建议：**先做 P0-B 验证方向（半天），再上 P0-A（正式方案）。**

#### P1 —— 顺手把 `HALL_LOST_DECAY_RS` 用起来

把 `bsp_encoder.c:885-890` 的硬清零改成"按时间常数衰减到某个下限"（配置里已经有 `HALL_LOST_DECAY_RS 60.0f` 这个宏，正好是给它用的），至少让丢边沿后角度不会瞬间"死"：

```c
if (lost > (uint32_t)s_lost_limit) {
    s_phase_trim = 0.0f;
    s_angle_spd *= (1.0f - HALL_LOST_DECAY_RS * ts);   /* 而不是 = 0 */
    if (fabsf(s_angle_spd) < 0.2f) s_angle_spd = 0.0f; /* 防止长期微积分漂移 */
}
```

注意：**这不能替代 P0-A**——因为 60° 扇区钳位还在，衰减最多再推进 60° 电角就撞墙了，对"持续旋转"没用。它只是让起停过渡更顺。

#### P2 —— 提高标定/对齐可靠性（相位误差会直接吃掉转矩）

`ALIGN_CURRENT_ID = 0.5A`。如果转子在 0.5A 下没能完全对齐到施加的 d 轴（被齿槽卡在 ±30° 内），`s_zero_ofs` 就会带一个**系统性相位误差**，之后整个 FOC 的转矩都乘一个 `cos(δ)`。0.4A 阈值对应的 0.3→0.4 之间只有 6mN·m 差别，**cos(30°)=0.87 就能解释一半的阈值**。

建议：
- 把 `ALIGN_CURRENT_ID` 提到 0.8~1.0A 并延长 `ALIGN_TIME_MS` 到 1500ms，让转子彻底对齐（对齐是开环强拖，不会失控）；
- CALIB 阶段的开环斜坡 `HALL_CALIB_RATE` 适当放慢（120°/s 已经比较保守，可保持），并把 `HALL_CALIB_TOL` 收到 15°。

## 3. 问题②：速度模式 100rpm 一转一停、明显卡顿

### 3.1 主因链（RC2 + RC3 合起来是一个典型的 stick-slip 极限环）

把 `PID_FrictionFeedforward`（`PID.c:219-302`）和 `PID_Speed_Loop`（`PID.c:308-392`）连起来看，100rpm 目标下的循环是：

```
          转速掉到 ≤10rpm
                │
                ▼
  进入 FRICTION_REST (PID.c:270-278)
    · 清空 pid.Integral / Error / Out
    · 之后每 1kHz 调用都把 pid.Integral = 0   ← PID.c:281
                │
                ▼
  ff 从 0.15A 在 150ms 内线性爬到 0.75A      ← PID.c:282-290
  （而实际脱开只需要 ~0.4A，所以是过冲式猛冲）
                │
                ▼
  转速窜到 ≥20rpm
                │
                ▼
  进入 FRICTION_MOVING：ff 立刻掉到 0.35A，
  80ms 内衰减到 0.15A                        ← PID.c:250-258 / 202-214
  同时 PI 的积分器"刚开始"从 0 恢复
                │
                ▼
  合力矩 < 动摩擦 → 转速再次掉到 ≤10rpm
                └────────────► 回到起点
```

一环扣一环：
- **前馈是"开关式"的**（0.75A → 0.35A → 0.15A 三档跳变），而不是连续的摩擦模型；
- **PI 积分器被每毫秒清零**（`PID.c:281`），所以"维持转速"的那部分力矩根本建不起来，整个速度环没有稳态力矩能力，只能靠前馈周期性猛冲——**一转一停**。

周期量级对得上：REST 爬升 150ms（+最多 500ms 放弃判据 `PID.c:282/291`）+ MOVING 释放 80ms ≈ 0.2~0.65s，100rpm 下一转 0.6s。

这与配置注释 `0.0025会增加停顿点，0.004已验证振荡` 完全自洽：**在一个"积分器被反复清零 + 前馈开关跳变"的结构里加 Kp，只会让 PI 更早要求反向 → 更早撞上禁刹钳位 → 停顿更多。**

### 3.2 帮凶 RC3：禁刹钳位让速度环失去减速权限

`PID.c:357-380`：

```c
if ((fabsf(rpm_target) >= 5.0f) && (fabsf(rpm_target) <= SPEED_NO_BRAKE_RPM /*200*/) &&
    (iq_raw * rpm_target < 0.0f)) {
    if (speed_along_target <= fabsf(rpm_target) + 30.0f /*OVERSHOOT_RPM*/) {
        iq_raw = 0.0f;                      /* ← 完全放弃制动 */
    }
    ...
}
```

100rpm 目标下，**只要转速在 0~130rpm 之间且 PI 想反向，Iq 一律被置 0**。也就是说：
- 100→130rpm 这一段 **没有任何制动力矩**，只能靠摩擦自然掉速；
- 想稳在 100rpm，速度环实际上是一个"只给正力矩 + 摩擦自由减速"的**欠阻尼 bang-bang**，必然出现周期性冲高-掉速。

注释写的是 `避免刹在下一个Hall边界`——这是一个**症状级的补丁**，掩盖了真正的问题（角度源在低速不可靠、PI 积分被清零导致制动时力矩抖动）。正确做法是把制动权限还给速度环，同时把角度源修好（P0-A）。

### 3.3 帮凶 RC4：反馈信息率与电流环相位裕度

- **信息率**：100rpm 时霍尔边沿 40Hz，扇区内的角度是**线性外推**，所以 `mech_rpm`（10ms 滑动窗净位移）**对扇区内的瞬时速度变化是"盲"的**，只反映扇区平均；再叠 30Hz 低通 → 有效延迟 ≈10ms。速度环的可用带宽应 ≲10Hz，而不是按 1kHz 采样率去设计。
- **相位裕度**：见 RC4/§0。三个 710Hz 一阶极点串在 300Hz 电流环里 → 相位裕度约 13°。电流环在低速小电流下本来信噪比就差（30 个码值），相位裕度又只有 13°，纹动会被放大到转矩上。

### 3.4 解决方案

#### P0-C：拆掉速度环里的自激结构（问题②的核心）

1. **删掉 `PID.c:281` 的 `sc->pid.Integral = 0.0f;`**，改成**积分限幅**：

```c
/* REST 状态：允许积分器把"脱开所需力矩"建起来并保持，只限制幅值 */
if (sc->pid.Integral >  SPEED_FRICTION_STATIC_A) sc->pid.Integral =  SPEED_FRICTION_STATIC_A;
if (sc->pid.Integral < -SPEED_FRICTION_STATIC_A) sc->pid.Integral = -SPEED_FRICTION_STATIC_A;
```

2. **把"缩减 PI 输出上限"改成"前馈与 PI 不再互相抢额度"**（`PID.c:339-351`）。要么保留 PI 的完整权限、前馈叠加后统一限幅；要么把前馈加到 PI *之前*。现在 `OutMax = SPEED_IQ_MAX - ff` 的写法在 `ff` 最大时反而把 PI 的权限压到 0.5A，是很别扭的耦合。

3. **把 `PID_FrictionFeedforward` 换成连续的摩擦模型**（Coulomb + 粘滞 + 低速度"起动助推"）：

```c
/* 建议的替换形式（去掉 4 状态机） */
float verr = rpm_target - fb_rpm;
float vmag = fabsf(fb_rpm);
float ff;
if (vmag < FRICTION_STICK_RPM) {            /* 近似静止：给动摩擦 + 一份"脱开"量 */
    ff = FRICTION_KINETIC_A * signf(rpm_target);
    ff += FRICTION_STATIC_EXTRA_A * satf(verr / FRICTION_STICK_RPM, -1.0f, 1.0f); /* 连续、无跳变 */
} else {
    ff = FRICTION_KINETIC_A * signf(rpm_target) + FRICTION_VISCOUS * fb_rpm;
}
iq_raw = pid_out + ff;                       /* 前馈是偏置，不是状态机 */
```

关键是 **ff 必须是 `rpm_target` 和 `fb_rpm` 的连续函数**，不能有 0.75→0.35 的阶跃，也不能和积分器互相清零。

4. **放开禁刹钳位**（`PID.c:357-380`）：只保留"目标方向与实际方向相反时不允许反向拖"这一个真正的保护（即 `rpm_target` 和 `fb_rpm` 异号时），**删掉 `目标±30rpm` 那一段**。制动力矩是速度环稳速的必要权限。

5. 上述改完后，**速度环 Kp/Ki 需要重新整定**：先把 Ki 归 0、只调 Kp 到临界振荡再退一半，然后加 Ki。用 §4 的新增观测通道看波形，目标：转速纹波 <±10rpm、Iq 无周期性跳变。

#### P0-D：修好角度源（P0-A 同时解决问题②里"掉速就停"的部分）

100rpm 时 `lost_limit = 75ms`（`3×25ms`），所以稳态下不会冻结；**但一旦卡顿把转速压到 40rpm 以下，边沿间隔 >62ms，一旦超过 `3×周期` 或 40ms 下限，角度就会冻结 → 彻底停住 → 只能等前馈猛冲。** P0-A 的助推覆盖了这一段（`ANGLE_ASSIST_RPM_ENTER = 60rpm`），把这个恶性循环从根上切断。

保险起见可以把 `HALL_EDGE_LOST_RATIO` 从 3 提到 4~5，让 40~60rpm 段有更多余量（代价是真正停转后角度会多外推一会儿，但 P0-A 会覆盖这段）。

#### P1-A：给电流环留相位裕度

`filter.c:546-548` 把 `Iu_filter/Iv_filter/Iw_filter` 的 α 从 `0.2f` 改成 `0.5f`（≈2.2kHz 极点，300Hz 处只吃 ~8°×3=23°）或直接 `1.0f` 旁路。如果旁路后 PWM 上出现可见噪声，优先去改 ADC 采样时间（P1-B）而不是把滤波器加回来。

也可以在改滤波器的同时把 `CURRENT_BW_HZ` 从 300 降到 200，两者都做等于留了很大余量。

#### P1-B：ADC 注入采样时间 3 → 28 或 56 周期

`adc.c:78`：`sConfigInjected.InjectedSamplingTime = ADC_SAMPLETIME_3CYCLES;`
- ADCCLK = 84MHz/4 = 21MHz → 3 周期 = 143ns。电流采样运放的输出阻抗 + 4pF 采样电容，143ns 通常充不满，会引入随信号幅度变化的增益误差，**小电流时相对误差最大**。
- 改成 `ADC_SAMPLETIME_28CYCLES`：单次 ≈ (28+12)/21MHz = 1.9µs，3 次 ≈ 5.7µs，在 50µs 周期内绰绰有余（触发在计数器峰值附近，零矢量窗口足够宽）。
- 这是改动最小、收益很直接的一项，**建议和 P1-A 一起做**。

#### P1-C：死区补偿（RC5）

`Core/Src/tim.c:139` 的 `DeadTime = 60` ≈ 357ns，占 50µs 周期的 0.714%，对应每相平均电压误差：

```
ΔV_dead = (Tdead / Tsw) * Udc = (0.357µs / 50µs) * 24V ≈ 0.171 V
```

而 0.3A 在 q 轴只需要 `R*Iq = 0.125V`。补法（在 `PI_Current_Loop` 之后、SVPWM 之前，或直接在 `FOCParm.Vd/Vq` 上）：

```c
/* 用三相电流符号的 dq 投影做补偿；近零电流用线性过渡避免抖动 */
#define DEAD_TIME_S     357e-9f
#define DEAD_TIME_V     ((DEAD_TIME_S / (1.0f/Tim_Hz)) * _Udc)   /* ≈0.171V */
#define DEAD_IZERO_A    0.05f

float cu = lin_sign(iu, DEAD_IZERO_A);   /* i>iz→+1, i<-iz→-1, 中间线性 */
float cv = lin_sign(iv, DEAD_IZERO_A);
float cw = lin_sign(iw, DEAD_IZERO_A);
/* 三相等效到 dq（用同一 Theta） */
float ca = cu;                                    /* α 轴 */
float cb = (cu + 2.0f*cv) / SQRT3;                /* β 轴 */
float cd =  ca*cosf(Theta) + cb*sinf(Theta);
float cq = -ca*sinf(Theta) + cb*cosf(Theta);
Vd -= DEAD_TIME_V * cd * 0.5f;   /* 系数需实测标定，符号也要实测确认 */
Vq -= DEAD_TIME_V * cq * 0.5f;
```

注：系数/符号必须**实测标定**，不要照抄。标定方法：开环给固定角度+固定 iq 指令，看 `Iq实际` 与指令的偏差随电流符号的变化。

#### P2：把速度反馈观测器真正做起来（`PLL_Loop` 是死代码）

`Users/Src/StateMachine.c:57-58` 初始化、`197-205` 用 `HALL_GetElecOmega()` 对齐了 PLL 状态，注释明确写着"PLL 只作为转速观测器"——**但 `PLL_Loop()` 在整个工程里从未被调用**（grep 只有 `PLL.c/PLL.h/_backup_working`）。

把 `PLL_Loop(&state->PLLParm, mech_angle)` 接到 `Run_UpdateObserver()` 里（用机械角而不是电角，注意 wrap），就能得到一个**连续、无跳变、低延迟的机械转速估计** `RPM_FROM_WE(PLLParm.OutWe)`，比现在"10ms 净位移 → 30Hz 低通"的延迟小得多。建议把它和 `fused_rpm` 按转速加权融合（低速用 PLL、高速用单边沿 T 法）。这是解决问题②反馈质量的"正规"做法。

> 注意：PLL 的 `kp_theta=300 / ki_theta=20000` 是按电角、T=50µs 整定的，换成机械角要按极对数换算（机械角变化速率是电角的 1/PP）。先用 VOFA 看波形再定参数。

## 4. 强烈建议先补的观测通道（否则没法调）

现在 **速度模式 18 个通道里没有一路是"实际转速"**（`VOFA.c:37-57`），扭矩模式只有 Id/Iq 四路（`VOFA.c:29-34`），**在速度模式下调速度环等于闭着眼睛调**。

建议：
- `MOTOR_RUN_SPEED` 增加/替换 2~3 路：`Motor_GetSpeedFB()`（滤波后反馈）、`HALL_GetMechSpeedRpm()`（10ms 净位移）、`RPM_FROM_WE(PLLParm.OutWe)`（PLL 观测）、`MotorBLDC.speed.friction_state`、`ff` 值。
- `MOTOR_RUN_TORQUE` 增加：`Motor_GetSpeedFB()`、`FOCParm.Theta`（电角度，看它是否在动）。
  ——**只要在扭矩模式看到 `Theta` 不动而 `Iq` 稳定，就一眼确认 RC1。**
