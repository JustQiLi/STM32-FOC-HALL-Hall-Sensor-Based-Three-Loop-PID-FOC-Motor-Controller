# STM32-FOC-HALL：Hall-Sensor-Based Three-Loop PID FOC Motor Controller

## 基于霍尔传感器的三环 PID 控制系统

> 基于 STM32F407 的 **20kHz 电流环 / 1kHz 速度环 / 200Hz 位置环**三轴串级 FOC 实现，支持**转矩 / 速度 / 位置三模式**在线切换。
>
> 仅用 **三路霍尔传感器** 完成转矩模式电流环跟踪偏差 < 0.005A，速度模式 5–3600 rpm 全区间速度闭环（±1.5%），实测稳定区间100-3000rpm，速度过低会较明显抖动，位置模式正向到位精度 < 1.5°。
>
> 内置 **18 项补偿机制**（摩擦前馈 / 死区补偿 / 角度助推 / PLL 观测器 / 抗积分饱和等）。
>
> 使用自定义的QiLi FOC算法库（包括传统SVPWM以及零序注入法）。
>
> 支持 VOFA+ 在线调参与实时遥测。

### 1.1 核心亮点总览

<div align="center">

| 序号 | 亮点 | 做了什么 | 解决了什么问题 | 实测效果 |
|:---:|---|---|---|---|
| 1 | **仅用霍尔实现低速闭环** | 角度助推(I/F蠕动) + PLL转速观测器 + 丢边沿衰减处理，三路配合让低速估算角持续推进 | 霍尔15°分辨率在低速下严重量化，传统方案丢边沿后估算角冻结→电流矢量静止→转子被吸住→永久锁死 | 50rpm稳定运行（修复前完全锁死0rpm） |
| 2 | **摩擦前馈状态机** | 四状态前馈(REST→MOVING→BRAKE)，静摩擦0.75A破障→释放0.35A过渡→动摩擦0.15A维持 | 静摩擦门槛(0.15-0.4A)导致启动困难、低速振荡；传统PI要么力矩不足粘住，要么积分饱和突跳过冲 | 50rpm稳态Iq从0.79A降至0.19A，无过冲振荡 |
| 3 | **死区电压补偿** | 按三相电流符号投影到dq轴叠加0.171V补偿，零电流区线性过渡 | 逆变器357ns死区造成0.171V电压损失，而维持0.3A只需0.125V，不补偿小电流指令本身就是"糊"的 | 0.19A小电流下Iq跟踪偏差<0.003A |
| 4 | **零极点对消电流环整定** | 用电机R/L直接计算Kp=L·ωc·2π, Ki=R·ωc·2π，带宽300Hz | 手动整定PI参数困难，相位裕度难以保证 | 电流环跟踪偏差<0.005A |
| 5 | **PLL转速观测器** | 二阶PLL跟踪连续机械角(霍尔边沿+估算内插)，输出平滑转速+15Hz低通 | 霍尔单边沿T法测速有60°量化台阶+10ms延迟，速度环对台阶过激响应导致Iq猛冲→自激振荡 | 反馈与真值一致到0.4–2.4%，无量化噪声 |
| 6 | **上电自标定流程** | 两次对齐(0°/180°)→零位细分标定(缓慢拖动跨边沿)→转矩方向自检(Iq=0.25A探极性) | 霍尔零位不确定(±30°)、方向二义性导致上电飞车 | 零位误差从±30°压到几度，上电无飞车 |
| 7 | **抗积分饱和(非对称钳制)** | 正向低速钳制(0.15+0.0008×目标转速)、负向0.50A、Iq斜率100A/s三重限制 | 小目标时积分无上限瞬间给满2A，导致过冲-刹回振荡 | 阶跃响应无明显超调 |
| 8 | **VOFA+在线调参遥测** | 自定义JustFloat二进制协议+文本命令解析，DMA非阻塞收发 | 每次调参都要重新烧录，调试效率低 | 实时修改id/iq/rpm/pos/PID增益/模式切换，免烧录 |

</div>

### 1.2 调试方法论

- **取证级调试**：同一串口流内同时解析固件转速反馈和固件输出电角度，用净转数法独立验证反馈标度，定位了"反馈链5×增益误差"的误判（实际根因是低速锁死bug，角度助推被一行`return 0`关掉）
- **二进制帧相位锁定**：自定义JustFloat协议解析器，通过连续帧尾匹配实现相位锁定，支持丢帧重同步
- **安全采集脚本**：Python脚本实时监控转速/电流，超过阈值自动发停机命令，硬件调试零风险

### 4.1 三环串级控制架构

```
位置指令(°) → [位置环 200Hz] → 速度指令(rpm) → [速度环 1kHz] → Iq指令(A)
                                                                          ↓
三相电流 ← [SVPWM] ← [死区补偿] ← [电流环 20kHz] ← Clarke/Park ← ADC采样
                ↑                                              ↑
           TIM8 20kHz                                    电角度观测
          (PWM+ADC触发)                              (霍尔+PLL+助推)
```

<div align="center">

| 控制环 | 频率 | 实现方式 | 周期 |

## 五、核心补偿机制详解

> 本项目共实现 **18 项补偿机制**，分布在电流环(4项)、速度环(9项)、位置环(5项)。
> 每一项均按「做了什么 → 解决了什么问题 → 参数/代码位置 → 实测效果」展开。

### 5.1 电流环补偿（4项）

#### 5.1.1 死区电压补偿

- **做了什么**：在Park变换之后、SVPWM之前，按三相电流的符号把死区电压损失投影到dq轴，叠加到Vd/Vq输出上；当|i|<0.05A时线性过渡，避免零电流附近的正反馈抖动。
- **解决了什么问题**：逆变器上下管死区时间Tdt=357ns，造成每相平均电压损失 ≈ (Tdt/Ts)·Udc = (357ns/50µs)×24V ≈ 0.171V。而静止维持0.3A只需I·R=0.125V——不补偿的话，低Iq指令本身就是"糊"的，表现为低速力矩不足和电流零点畸变。
- **参数**：`DEAD_TIME_V=0.171V`，`DEAD_IZERO_A=0.05A`，`DEADTIME_COMP_SIGN=1.0`
- **代码位置**：`Deadtime_Compensate()` in `Users/Src/StateMachine.c`
- **实测效果**：0.19A小电流下Iq跟踪偏差<0.003A，低速力矩充足。

#### 5.1.2 电流采样滤波整定

- **做了什么**：将三级串联一阶低通滤波器的系数从0.2改为0.4。
- **解决了什么问题**：原系数0.2对应极点≈710Hz，三级串联在300Hz电流环带宽上吃掉约69°相位，相位裕度只剩十几度，容易引发电流环振荡。改为0.4后极点≈1.6kHz，相位损失减半。
- **参数**：`CURR_FILTER_ALPHA=0.40`
- **代码位置**：`Users/Inc/Motor_Config.h`，加载点在`Users/Src/StateMachine.c`初始化段

#### 5.1.3 零极点对消法电流环整定

- **做了什么**：不用手调，直接用电机的实际相电阻R和相电感L计算PI参数：Kp = L·ωc·2π，Ki = R·ωc·2π，电流环带宽设为300Hz。
- **解决了什么问题**：手动整定PI参数困难，且难以保证相位裕度；用电机物理参数直接定标，一次到位。
- **参数**：MOTOR_R=0.415Ω，MOTOR_L=1.24mH → Kp=2.34，Ki=782.3
- **代码位置**：`Users/Inc/Motor_Config.h`
- **实测效果**：电流环跟踪偏差<0.005A。

#### 5.1.4 输出限幅 / 抗积分饱和

- **做了什么**：电流环PI输出限幅在SVPWM最大不失真电压Udc/√3=13.856V，积分同步限幅防止电压饱和后继续累积。
- **解决了什么问题**：电压饱和后积分继续累积，退饱和时产生电流冲击。
- **参数**：`CURRENT_OUT_MAX = Udc/√3 = 13.856V`
- **代码位置**：`Algorithm/Src/PID.c` 的 `PI_Current_Loop()`

---

### 5.2 速度环补偿（9项）—— 本项目最核心

#### 5.2.1 ⭐ 摩擦前馈状态机（最亮点）

- **做了什么**：实现四状态前馈状态机：
  - `REST`（静止）：目标速度非零时立即给`START_A=0.50A`破障，150ms内爬升到`STATIC_A=0.75A`
  - `MOVING`（转动）：前馈降至`KINETIC_A=0.15A`维持转动
  - 刚脱开静摩擦时保留`RELEASE_A=0.35A`，80ms平滑降至动摩擦电流，防止转矩突降导致再次停转
  - `BRAKE`（超速）：关闭补偿，交给自然摩擦减速
- **解决了什么问题**：静摩擦门槛约0.15–0.40A，开环实测0.10–0.16A全部是"粘住→突跳"的粘滑状态。传统PI在低速时要么力矩不足（粘住不动），要么积分饱和（突跳过冲→刹回→振荡）。四状态前馈在PI出力之前就把静摩擦"填平"，PI只负责动态调节。
- **参数**：`SPEED_FRICTION_STATIC_A=0.75`，`KINETIC_A=0.15`，`RELEASE_A=0.35`，`START_A=0.50`
- **代码位置**：`PID_FrictionFeedforward()` in `Algorithm/Src/PID.c`
- **实测效果**：50rpm稳态Iq从修复前的0.79A（低速钳制用满）降至0.19A，无过冲振荡。

#### 5.2.2 ⭐ 角度助推（I/F蠕动）—— 解决低速锁死

- **做了什么**：当命令了Iq电流且转速低于25rpm时，让电角度估算器按10rad/s（≈24rpm机械）的"蠕动速度"继续旋转（开环I/F硬拖），转子跟着转过15°机械角就产生新的霍尔边沿，随即交回霍尔闭环；转速高于45rpm时退出助推（迟滞防止边界振荡）。
- **解决了什么问题**：霍尔在零速/极低速下给不出转子在60°扇区内的细分位置。丢边沿后若估算角停止推进，电流矢量就静止在定子上，转子永磁d轴被吸到Δ=0，转矩=Kt·Iq·cos(Δ)→0，转子不动又永远没有新边沿→**永久自锁**。这是本项目调试中最隐蔽的bug——代码里一行`return 0`把速度模式的助推关掉了，导致50rpm完全不转。
- **参数**：`ANGLE_ASSIST_W_CREEP=10.0rad/s`，迟滞`RPM_ENTER=25`/`RPM_EXIT=45`
- **代码位置**：`AngleAssist_Creep()` in `Users/Src/StateMachine.c`
- **实测效果**：50rpm从完全锁死(0rpm)→49–50rpm稳定运行；100rpm从反复停转→97–101rpm。

#### 5.2.3 丢边沿衰减处理

- **做了什么**：丢边沿后分两支处理：有助推请求时按±W_CREEP推进估算角；无请求时按60rad/s²线性衰减到0（不直接清零），且助推期故意不夹60°扇区，让估算角开环越过边界产生新边沿。
- **解决了什么问题**：旧代码丢边沿后直接清零估算角速度→角度冻结→自锁。线性衰减保证角度平滑过渡，不会突然冻死。
- **参数**：`HALL_LOST_DECAY_RS=60.0rad/s²`
- **代码位置**：`BSP/Src/bsp_encoder.c`

#### 5.2.4 转矩抬底

- **做了什么**：堵转状态下且目标|iq|<FLOOR时，实际输出电流抬到0.50A（大于齿槽/静摩擦临界值约0.40A），转子启动(>30rpm)后回到用户目标值。
- **解决了什么问题**：小目标下速度环PI输出的电流不足以克服静摩擦起转，转子一直粘在原地。
- **参数**：`CURR_BOOST_FLOOR_A=0.50`，迟滞`RPM_IN=10`/`RPM_OUT=30`
- **代码位置**：`Users/Src/StateMachine.c`

#### 5.2.5 ⭐ PLL转速观测器

- **做了什么**：用二阶PLL跟踪连续机械角（霍尔边沿+估算内插），输出连续平滑的机械角速度，输出后再加15Hz低通进一步衰减换相台阶尖峰。
- **解决了什么问题**：霍尔单边沿T法测速有60°量化台阶+10ms窗口延迟，速度环对台阶过激响应导致Iq猛冲→力矩冲击→自激振荡。PLL输出无采样保持台阶，延迟远小于窗口测速。
- **参数**：`kp_theta=300`，`ki_theta=20000`，`SPEED_PLL_LP_HZ=15Hz`
- **代码位置**：`PLL_Loop()` in `Algorithm/Src/PLL.c`
- **实测效果**：反馈与真值一致到0.4–2.4%，无量化噪声。

#### 5.2.6 PLL输出速率钳位

- **做了什么**：PLL输出每帧变化量钳位在±300rpm（真实物理上限≈170rpm/帧）。
- **解决了什么问题**：霍尔换相瞬间角度台阶造成转速尖峰，速度环不应对台阶做过激响应。
- **代码位置**：`Users/Src/StateMachine.c`

#### 5.2.7 低速禁反向制动

- **做了什么**：200rpm以下同向运行时不输出反向制动Iq，交给自然摩擦减速。
- **解决了什么问题**：低速下反馈抖动会让PI发出反向电流，把电机刹停并进入振荡。
- **参数**：`SPEED_NO_BRAKE_RPM=200.0`
- **代码位置**：`Algorithm/Src/PID.c`

#### 5.2.8 抗积分饱和（非对称钳制）

- **做了什么**：三重钳制：
  - 对称上限：`SPEED_IQ_MAX/Ki = 2.0/0.01 = 200`
  - 负向钳制：`SPEED_IQ_NEG_LIM_A/Ki = 0.50/0.01 = 50`（刹车后积分最深-0.50A，恢复期仍有正向保持力矩，无转矩真空）
  - 低速正向钳制：`(0.15 + 0.0008×目标转速)/Ki`（仅目标转速≤200rpm，防止小目标时积分瞬间给满）
- **解决了什么问题**：小目标时积分无上限瞬间给满2A，导致过冲-刹回振荡；非对称钳制保证刹车后仍有正向保持力矩。
- **代码位置**：`Algorithm/Src/PID.c`
- **实测效果**：阶跃响应无明显超调。

#### 5.2.9 Iq指令斜率限幅

- **做了什么**：速度环输出的Iq指令变化率限制在100A/s。
- **解决了什么问题**：指令跳变引起机械冲击和估算角跟不上。
- **参数**：`SPEED_IQ_SLEW_A_S=100A/s`
- **代码位置**：`Algorithm/Src/PID.c`

---

### 5.3 位置环补偿（5项）

#### 5.3.1 破静摩擦启动补偿

- **做了什么**：位置环指令≥10rpm（对应位置误差≥~2.9°）且转子静止时，Iq抬底到0.65A破障；转子启动后撤除交回速度环。
- **解决了什么问题**：位置阶跃时速度环输出力矩不足以跨过齿槽，转子停在目标附近不动。
- **参数**：`POS_BOOST_A=0.65`，`POS_BOOST_CMD_RPM=10`，迟滞`RPM_IN=10`/`RPM_OUT=30`
- **代码位置**：`Algorithm/Src/PID.c`

#### 5.3.2 单圈绝对角 + 最短路径误差

- **做了什么**：位置反馈用`fmod`归一化到[0,2π)单圈角，位置误差走最短路径（±180°）。
- **解决了什么问题**：累计机械角可达几万度，直接与目标[0,360°)相减会产生巨大误差→位置环饱和乱推。
- **代码位置**：`Run_PositionMode()` in `Users/Src/StateMachine.c`

#### 5.3.3 位置反馈低通 + 切入重置

- **做了什么**：切入位置模式时将低通滤波器状态和输出prev值对齐到当前真值。
- **解决了什么问题**：ST-LINK烧录复位不清SRAM，static变量残留会造成启动猛冲。
- **代码位置**：`Users/Src/StateMachine.c`

#### 5.3.4 位置输出斜率限制

- **做了什么**：位置环输出（速度指令rpm）每5ms最大变化率限制为2rpm。
- **解决了什么问题**：目标切换时的机械冲击，防止高KP饱和猛冲→目标附近bang-bang极限环。
- **参数**：`POS_OUT_RATE_RPM=2.0`
- **代码位置**：`Run_PositionMode()` in `Users/Src/StateMachine.c`

#### 5.3.5 位置专用助推

- **做了什么**：位置模式下独立的蠕动速度（3rad/s≈7rpm机械），由位置误差方向引导单向慢拖。
- **解决了什么问题**：位置模式下同样会丢边沿自锁；注意位置模式不使用速度模式的角度助推（`AngleAssist_Creep()`对位置模式返回0），有独立通道。
- **参数**：`HALL_CREEP_W_POS=3.0rad/s`
- **代码位置**：`Users/Src/StateMachine.c`

## 八、已知不足与改进方向

<div align="center">

| 序号 | 不足 | 影响 | 改进方向 |
|:---:|---|---|---|
| 1 | **位置模式回程不到位** | 反向运动最大误差-118.6°，Iq已达-1.05A仍无法反向转动 | 检查位置模式反向摩擦补偿的方向逻辑；适当提高`POS_RPM_MAX`；增加回程专用补偿 |
| 2 | **电流采样固定偏置≈+0.13A** | 小电流指令时Iq实测偏高（0指令时仍报0.13–0.15A） | 运行期动态零点校准；开启扇区无效相修正 |
| 3 | **速度帧缺转速通道** | 速度模式18通道中无直接rpm反馈，需从电角度推算 | 在`VOFA.c`速度分支增加`Motor_GetSpeedFB()`通道 |
| 4 | **位置分辨率下限7.5°** | 位置稳态误差std 5–11°，受半个霍尔台阶支配 | 改用编码器/磁编码器；或增加观测器插值精度 |
| 5 | **低速瞬时纹波±25%** | 50rpm瞬时转速波动大（均值准确） | 系机械粘滑本性，可尝试更高分辨率反馈或非线性PID |
| 6 | **转矩模式大电流电压饱和** | ≥0.5A时转速进入3300rpm平台，Iq跟踪变差 | 系24V母线电压限制，硬件层面无法避免；可弱磁扩速 |
| 7 | **位置环输出限速40rpm** | 大角度阶跃响应时间长 | 可提高到60–80rpm（需重新整定速度环参数） |

</div>

## 九、快速开始

### 9.1 环境要求

- Keil MDK-ARM 5.x（工程文件在`MDK-ARM/`）
- STM32CubeMX 6.x（可选，用于重新配置引脚）
- VOFA+ 上位机（用于调参和波形观察，官网：https://www.vofa.plus/）
- Python 3.8+（用于数据采集和分析，需安装依赖）

### 9.2 编译烧录

1. 用Keil打开 `MDK-ARM/Base_Project.uvprojx`
2. 编译
3. 用ST-LINK烧录

### 9.3 上电运行

1. 上电后电机自动执行：对齐(0°)→对齐(180°)→零位标定→方向自检→进入RUN状态（约3–4秒）
2. 默认进入转矩模式(`m0`)，Iq=0，电机静止
3. 打开VOFA+，选择串口，波特率921600，协议选**JustFloat**

### 9.4 基本操作示例

```
# 切换到速度模式，给定1000rpm
m1
rpm=1000

# 切换到转矩模式，给定0.3A
m0
iq=0.3

# 切换到位置模式，转到180°
m2
pos=180

# 紧急停机（任何模式下都有效）
iq=0
rpm=0
```

### 9.5 数据采集与分析

```bash
# 安装Python依赖
pip install pyserial matplotlib numpy pandas

# 三模式综合采集（带安全保护，超限自动停机）
python Python/foc_capture.py --mode 0  # 转矩模式
python Python/foc_capture.py --mode 1  # 速度模式
python Python/foc_capture.py --mode 2  # 位置模式

# 生成分析报告和可视化图表
python Python/foc_analysis_report.py
```

> 采集脚本内置安全保护：实时监控转速和电流，超过`rpm>4200`或`|Iq|>2.5A`立即发送`rpm=0`/`iq=0`并中止采集。

## 附录 B：VOFA+ JustFloat 协议说明

### 帧结构

```
[float1][float2]...[floatN][0x00][0x00][0x80][0x7F]
```

- 数据段：N个小端序float32（N=通道数）
- 帧尾：固定4字节 `00 00 80 7F`
- 帧长 = 通道数 × 4 + 4

### 命令格式（文本，以`\n`结尾）

<div align="center">

| 命令 | 功能 | 示例 |
|---|---|---|
